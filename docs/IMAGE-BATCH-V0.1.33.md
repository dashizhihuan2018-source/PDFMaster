# V0.1.33 / build55：批量图片导入与PDF体积

修复手机照片在批量导入时，第六张左右就因累计超过1亿像素而整批失败的问题。拖入合并与直接图片转PDF采用同一20亿像素工作预算，逐文件/逐页释放临时解码对象。保留单帧4000万像素、500页、512MiB输入及256MiB输出等上限；拖入合并最多128个文件。不是无限大小导入，也不承诺系统解码器的内部峰值内存有硬上限。

JPEG从原图源创建图像，保留可嵌入PDF的JPEG压缩数据。EXIF方向与镜像由PDF绘制变换处理，避免为了旋转先生成完整位图缩略图。合并、保存并重新打开后，已验证JPEG压缩熵数据和像素宽高保持。

HEIC/HEIF不能直接作为标准PDF图片流嵌入，因此转换为JPEG，质量0.7、保留像素宽高、不降采样；透明HEIF对白底合成。该路径为有损转码，转为8位sRGB，不承诺无损或HDR/色彩逐像素不变。PNG/TIFF继续使用原有路径。输出大小随内容变化，不保证总小于原图片。

2026-11-12后台验证：原75张HEIC成功转换为75页，共170,613,114字节，原图片SHA-256全部不变；之前前六张就出现累计像素超限。合成高熵JPEG、EXIF1–8方向、透明PNG、超过1亿像素的批次、合并保存重开、取消/失败不发布及原生打包测试共64项通过。JPEG回归检查实际PDF图像XObject尺寸和压缩熵数据，不能仅凭页数或页面尺寸认为图像没有改变。

未进行前台桌面操作、其它Mac或所有图片编码组合验收。App已安装为V0.1.33/build55，签名及主程序哈希回读一致，安装后未自动启动。Apple Silicon arm64、macOS14及以上，ad-hoc签名、未获Apple公证的预发布。

# PDF Master Rust — migration candidate

This is an **in-progress full rewrite**, not the installed PDF Master replacement and not a feature-complete release. Business logic and UI are authored in Rust. Leptos compiles the UI to WASM; Tauri uses platform WebViews, generated JS glue and system SDKs. Those dependencies are not falsely described as Rust implementations.

**Delivery boundary:** the dedicated Apple-native version remains the local daily-use application. This Rust rewrite is for public Git sharing and cross-platform development; isolated test candidates do not replace or install over the Apple-native application. Public source, build artifacts, actual platform runtime and full UI/feature acceptance remain separate gates.

**UI fidelity is mandatory, not optional styling.** Preserve the original PDF Master interface and workflows as well as functionality. The current migration workbench is not the final UI. [UI-PARITY.md](UI-PARITY.md) records the inspected original layout/palette, required screens and visual/interaction gates. No original-UI or full-replica acceptance is claimed.

## Structure

- `crates/pdfmaster-core`: transactional PDF operations and rendering via lopdf / hayro. Unsupported cases fail explicitly; complex geometry, Unicode content editing and several resource classes remain incomplete. It is **not yet approved for arbitrary untrusted PDFs**.
- `crates/pdfmaster-drawing`: shared bounded midpoint/quadratic smoothing and quarter-turn point mapping for preview and PDF InkList; retains the original SwiftyDraw-derived MIT attribution.
- `app`: Leptos Rust UI; no handwritten JavaScript application frontend.
- `app/src/home.rs`, `app/src/shell.rs`, `app/shell.css`: original-derived home/sidebar/tool catalog and home/current-document navigation. Switching views preserves the single native session and form inputs; busy/note/Ink guards prevent hiding unfinished editors. Multi-document tabs, original icon assets and recents/favorites persistence remain incomplete.
- `app/src/workbench.rs`, `app/src/workbench_view.rs`, `app/workbench.css`: original-derived three-group reader toolbar, six primary modes, ordered secondary tool strips and context-only tool panels. Unsupported actions remain disabled; page copy is not falsely wired to duplicate. Narrow windows retain all groups in scrollable rows. Exact icons, continuous/dual layouts, inline editors and original-UI acceptance remain pending.
- `app/src/thumbnails.rs`, `app/src/thumbnail_view.rs`: real native page rasters in the original 124×164 thumbnail box, with bounded visible rows/cache, one active request, stale-document rejection and explicit failure/retry. Timeout pauses the loader rather than starting work behind an unobserved native request. Window resize and phone scrolling preserve the bounded viewport. Overview, multi-selection, drag reorder and actual three-platform interaction/visual acceptance remain pending.
- `outline_document` projects the current session's outline without editing it: Unicode/group titles, preorder paths and current local-page destinations, including separate legacy-name and modern-byte-string lookups. External/remote/ambiguous actions cannot navigate. Iterative traversal, reference/cycle checks and item/depth/text/name/lookup budgets bound reads. The original-order four sidebar selectors expose thumbnails/outline/search/annotations. Outline rows use the source's 54px/12px/two-line title and page suffix; bounded single-flight UI state rejects old-document replies. Destination coordinates/zoom, exact native symbols/skin and full sidebar parity are not implemented by this page-only slice.
- `annotations_document` and `app/src/annotation_view.rs` provide a bounded read-only document-wide annotation list, excluding Widget/Link/Popup while preserving actual page/object/array-slot identity. Unicode contents, type, basic device color and validated PDF modification dates feed the original-derived 44/60px rows, 11px text and 10.5px local timestamps. Page/newest sorting, page navigation, bounded clipboard-summary copying and the original-derived empty-state vector/tools are exposed. Document replacement invalidates rows/selection; stale replies cannot refill the new generation, and timeout suspends reads. Exact rectangle navigation, selected-text excerpts, generic deletion, PDFKit-inferred default colors and ICC conversion remain pending; generic delete/highlight creation stay disabled. This is not full annotation or UI parity.
- Search uses the original sidebar order: input, previous/next/cancel, status and 54px two-line results. Toolbar focus opens that one real list. A 180ms debounce and single-flight revision/ticket state coalesce rapid input, reject old/duplicate/cancelled/document-replaced responses and pause after unobserved native timeout. Search input alone may remain enabled during its own request; editing/Ink/missing-document and other busy operations still block it. An optional disclosure retains case-sensitive search and explains limitations. This remains bounded page-local plain-text search without PDF page labels, glyph coordinates or highlighted page selection; exact native controls and full three-platform UI parity remain pending.
- `src-tauri`: native dialogs, guarded desktop lifecycle, private local draft journal and no-clobber desktop export. A Rust UIKit adapter stages the complete PDF before iOS export and verifies provider readback; local simulator cancel/save/reopen has been exercised. Remote providers and physical devices remain unverified.
- `cross-platform/parity.json`: 801 legacy XCTest method contracts; all three platforms remain pending until actual ported-contract evidence is attached. This is not a complete UX inventory and not a test pass report.
- `tools/baseline.rs`: read-only legacy contract extractor using Rust std.

## Pinned toolchain

The reader sidebar also supports a user-requested resizable right separator. Its shared local width preference survives mode switches, hiding/showing and application restart; the original 176px default is retained. The usual 152–480px range is additionally bounded to leave 200px of reading workspace. Temporary viewport clamps do not overwrite the stored preference. Pointer cancellation rolls back an unfinished drag; keyboard arrows/Home/End offer the same bounds. Only the numeric preference is stored locally, and failed storage is disclosed. Three-platform drag/visual acceptance is still required.

Rust 1.96.0, Tauri CLI 2.12.4, Trunk 0.21.14. Cargo.lock files are committed for the independent core, UI and native workspaces. Use rustup's cargo rather than an unrelated system cargo. Set `NO_COLOR=true`; Trunk rejects the host convention `NO_COLOR=1`.

```sh
rustup target add wasm32-unknown-unknown aarch64-apple-ios-sim aarch64-apple-ios
cargo install trunk --version 0.21.14 --locked
cargo install tauri-cli --version 2.12.4 --locked
cargo test -p pdfmaster-core
cargo test --locked --manifest-path app/Cargo.toml --all-targets
cargo test --manifest-path src-tauri/Cargo.toml --lib --test security_contract
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
NO_COLOR=true cargo tauri build --debug --bundles app
```

On Apple Silicon, the installed `cargo-tauri` **must itself be arm64**. Installing under Rosetta generates Intel simulator settings that can persist even after reinstalling the CLI. Preserve an old generated project separately, then regenerate from the native CLI; do not delete source or user data. Xcode, CocoaPods, xcodegen and simulator runtimes are prerequisites.

```sh
NO_COLOR=true cargo tauri ios init --ci --skip-targets-install
NO_COLOR=true cargo tauri ios build --debug --target aarch64-sim --ci --no-sign --archive-only
```

An unsigned simulator archive is not an iPhone IPA, App Store release, TestFlight deployment or physical-device acceptance. Hosted Windows native builds/unsigned NSIS packaging have succeeded for documented older snapshots; current changes require their own exact-revision CI. Actual Windows installation/run and feature acceptance remain pending; do not interpret successful builds or target checks as Windows support.

## Data safety / release boundaries

- Edits operate on session bytes. Desktop export creates a new PDF without overwriting an existing path. iOS delegates destination selection/conflict handling to the system provider. Both validate parse and exact readback before clearing dirty state; original source files are not implicitly overwritten.
- Drafts stay in the candidate's private local app-data directory, with atomic replacement, 0600 files / 0700 directory on Unix, and an exclusive process lock. No cloud draft sync is implemented. Corrupt drafts are retained and block unsafe replacement.
- Normal dirty close/quit is blocked. Native macOS default Quit bypasses Tauri exit events, so the custom menu explicitly routes through `app.exit`. Unexpected OS termination is covered by the local draft journal, not by a claim that termination is impossible.
- The note-content editor acquires a snapshot-bound native session before exposing input. Normal close/quit and conflicting edits are guarded until explicit save/cancel. If the begin reply is lost, “同步便笺编辑状态” can recover the active session's original contents and ID in the current process; it cannot recover unpersisted typed text. Editor input is not crash-persistent, and the new guard's actual desktop/mobile interaction verification remains pending.
- Text-note deletion uses a native confirmation bound to exact PDF bytes and the current document epoch; reopening an identical PDF invalidates old note/page deletion prompts. Deletion is one undoable session edit, not secure erasure. Updating a note copies its owned popup, rebinds Parent/Popup and existing page backlinks, and preserves shared objects on other pages. Tagged notes, reply threads, ambiguous shared/duplicate-root popups and direct reverse-popup updates are not yet supported; the relationship scan caps at 16384 entries. Popup display, page-click selection and current-feature GUI acceptance are still pending.
- Export reserves the workspace from snapshot capture through the picker and target readback, without holding its mutex across provider I/O. Other mutations cannot race that snapshot; cancellation/error releases only the matching reservation. Unit tests do not replace native picker and asynchronous cancellation integration tests.
- Single-PDF insertion and a separate native multi-select batch entry import only page-reachable graphs, remap notes/local links, and commit the entire selected sequence as one undoable transaction. Any input failure leaves the current document/history unchanged. The batch follows the native picker's returned order (not a promised click order); temporary candidate limits are 32 files, 32MiB each, 64MiB combined input, 4096 total pages and 32MiB serialized output. Target metadata remains in place. Source forms/tagged structures, document-wide color/layer policies and conflicting document languages require further migration work and are explicitly rejected; reorderable merge UI, broader relationship migration and current-feature three-platform GUI acceptance remain pending.
- Text extraction resolves the nearest whole Resources dictionary, including direct/indirect inheritance and null-as-absent semantics, in a lazy read-only snapshot cached per successful document revision. A malformed page does not preflight-block unrelated valid pages. This does not add OCR, universal embedded-font support, or Unicode content editing.
- Rectangle/ellipse creation writes independent PDF Square/Circle annotations with appearance streams, opaque RGB stroke/optional fill and line width. Numeric bounds use unrotated source-page coordinates (bottom-left origin), even on rotated pages; their line width must be positive and smaller than either bound dimension. The current-page list supports numeric selection/update and native-confirmed deletion, with full expected geometry/style, exact-byte/epoch deletion checks, one undoable commit and owned Popup COW. Unknown metadata/shared annotations remain untouched. Imported extended/alpha/dashed Square/Circle styles, tags, replies and ambiguous relationships are not silently normalized. Saving/reopening and page extraction/insertion preserve appearances. Unapplied form parameters are not journaled or close-guarded; rerendering/navigation clears selection. Drag placement, alpha, ink and current-feature three-platform GUI acceptance remain incomplete; this is not the original full drawing workflow.
- Independent PDF Line annotations add explicit start/end numeric coordinates and plain/single/double-arrow creation. Endpoints must be distinct and inside the page (edges and horizontal/vertical lines are allowed); widths are 0.25–32pt inclusive. Numeric bounds updates scale the original endpoints without reversing direction and preserve ten standard ending styles and bounded BS/legacy Border dash patterns. Appearance bounds expand when necessary to fit thicker strokes/endings while retaining requested endpoint placement; page-edge clipping remains. Captions, leaders, opacity, measurement/intent semantics and unknown styles are not silently repainted. The existing snapshot/native-confirmed deletion, COW, history and save/extract/insert safeguards apply. This does not supply canvas placement/dragging, new ending/dash style controls, support for nonzero-origin/different CropBox PDFs, physical-device acceptance or a complete drawing replica.
- Shape creation currently shares the strict note admission validator: existing off-page/zero-area annotation rectangles or non-RGB Text-note colors can reject an addition without changing the document. This is a known compatibility gap, not a statement that such original PDFs are invalid; membership/count validation must be separated from editable-note validation during further migration.
- Ink pointer input freezes the page/style, uses CSS geometry rather than Retina raster coordinates, captures one pointer and commits one independent PDF Ink annotation with an appearance stream per stroke. Shared midpoint smoothing keeps preview and PDF polyline semantics aligned. Native epoch/bytes guards exclude conflicting edits/normal close; bounded IPC and request cancellation recover missing replies without cancelling a newer stroke or undoing an already committed one. A staged decoded-image handoff retains the preview until replacement succeeds and restores the old image on failure. Uncommitted samples are not crash-persistent; Ink selection, style updates, eraser and full three-platform interaction/fault-injection acceptance remain pending. Current-page shape/note lists deliberately count Ink among other annotations rather than claiming editable Ink support.
- Do not commit `target/`, `dist/`, generated native projects, private draft data, user PDFs, signing material, credentials or personal screenshots.
- Do not install this candidate over the formal application or publish it as full parity. Final delivery requires actual three-platform evidence, independent review, corresponding clean public source, package hashes and permitted signing/distribution.

# UI parity is a release requirement

用户于 2026-10-26 明确要求：Rust 重写不仅功能一致，UI 更要保持一致。不能用新的工作台设计、数值表单、功能演示壳或“相近风格”替代原版交互界面。原版产品与已授权源码是基准；参考第三方产品不是新的设计授权。

当前 Rust 候选 **未通过 UI 对等验收**。自动测试、同名按钮、CSS 数值和编译通过均不是视觉或交互一致的证明。

## 必需验收项（全部尚未完成）

- 首页：导航顺序、图标/品牌、标题/横幅、导入区、推荐工具卡片、最近与收藏、空/加载/错误状态；不能以虚假最近记录或无动作按钮凑外观。
- 标签壳：主页/多PDF/画布标签、文字截断、选中与悬停、关闭/新建、当前路由、脏状态及关闭取消；不能画出假标签而仍丢弃另一文档。
- 阅读工作台：原版深灰色调、缩略图、工具栏三组布局、二级批注工具、按需侧栏/Copilot、搜索、页码/缩放/单/双/连续页及面板弹出行为。
- 编辑流程：便笺、手绘、图形、正文等原版页面内定位/选择/拖动与编辑器、样式和键盘反馈。保留数据语义与Undo，不把全套交互替换成常驻右侧数值调试表单。
- 资源：复用已授权品牌/图标/字体及合法第三方署名；无法合法复用的资源单列缺口，不擅自设计替代后称一致。
- 弹窗与状态：打开/保存/权限拒绝/导出取消、未保存关闭、不可用工具、网络与AI账号状态，逐个核对文案、位置、焦点、启用状态和结果。
- 三平台：macOS/Windows 对同一原版基准逐屏对照；iOS保留信息架构、视觉标识和工具顺序，仅为系统导航、安全区、触控/键盘和窄屏作必要适配。所有平台适配差异须明确记录，不能自动算一致。

## 验证方法与当前差距

同一自造PDF、同一状态、同一内容区尺寸（桌面至少1280×820和1180×700；手机记录实际设备/安全区）分别运行原版和准确源码身份的候选。记录实际进程/包哈希，对照截屏和完整交互；标明系统窗口装饰、抗锯齿与平台控件差异。测量关键矩形/间距、颜色和字重；视觉核对与数据/引擎合同各自验收，不能互相替代。截图与用户资料不得默认公开。

2026-10-26 本机观察：候选仍是紫色强调色、浅色点阵阅读底、品牌标题行、常驻右侧数值工具栏与数字页面列表；缺原版首页、多标签和模式工具栏。它是迁移验证界面，不是已交付的原版 UI。现有 Ink 拖画/撤销/导出重开通过，不改变此结论。

下一阶段先建立真实首页/标签壳及会话路由，再逐区迁移原版工作台；不得只改颜色或把本文写好就宣布UI对等。完整UI验收是正式发布与最终 Rustall 技能总结的必要前提。
